## 7. Mail sistemi ✅

**Navbar → İletişim → Mail**, dört sekme: Gelen kutusu · Yeni mail · Ayarlar (+ Okunmamış/Yıldızlı/Arşiv).

**Sunucu ayarları** — SMTP · Resend · Postmark · SendGrid. Bağlantı test butonu var. Şifreler panele maskeli geliyor (`••••••••`); dokunmazsan eskisi korunuyor.

**Gelen mail** — IMAP değil, **inbound webhook**. IMAP kalıcı TCP bağlantısı ister, Next.js'te çalışmaz; sağlayıcı webhook'u üretimde doğru yöntem. Adres ayarlar sayfasında yazıyor:
```
https://<panel>/api/mail/inbound?secret=<inbound_secret>
```
Postmark, SendGrid, Resend ve genel JSON biçimleri destekleniyor. `message_id` benzersiz — sağlayıcı aynı maili tekrar gönderirse çift kayıt olmuyor.

**Akıllı eşleştirme** — mail geldiğinde tetikleyici gönderen adresini profillerle karşılaştırıp puanlıyor:

| Puan | Kural |
|---|---|
| 100 | `profiles.email` birebir |
| 95 | `auth.users.email` birebir |
| 70 | E-posta kullanıcı adı = username |
| 55 | Gönderen adı = profil ismi |
| 40 | İsim kısmi benzerlik |

Panelde "Bu maili gönderen kişi **X**" + güven etiketi (Kesin/Yüksek/Orta/Düşük) + gerekçe. Profil kartı tıklanabilir.

**Gönderim** — HTML / düz metin seçimi. HTML'de araç çubuklu editör: kalın, italik, altı çizili, başlık, liste, hizalama, **bağlantı, görsel, buton** ekleme. Ağır editör kütüphanesi (TipTap ~150KB) yerine `contentEditable` kullandım; bundle büyümedi.

**Varsayılan şablon** — ayarlardan düzenlenebilir. Değişkenler: `{{icerik}}` `{{konu}}` `{{logo}}` `{{imza}}`. 11 sistem şablonu da (güvenlik + reklam) panelden düzenlenebiliyor.

**Kuyruk mimarisi** — tetikleyiciler `mail_queue`'ya yazıyor, worker gönderiyor. Tetikleyicinin içinde SMTP beklemek kullanıcı kaydını yavaşlatırdı. `FOR UPDATE SKIP LOCKED`, 3 deneme, takılanları kurtarma, günlük limit kontrolü var.

**Kullanıcı detayında ikonlu Mail Gönder butonu** — alıcı otomatik seçili geliyor.

## 10. Güvenlik mailleri ✅

`auth.users` üzerinde `trg_security_mail`: şifre · e-posta · telefon değişikliği ve **yeni giriş** (cihaz + IP ile). Tüm gövde exception ile sarılı — **mail hatası auth işlemini bozmuyor**. Supabase'de auth şemasına trigger yetkisi yoksa migration bunu notice olarak söyleyip atlıyor.

## Reklam mailleri ✅

| Olay | Şablon |
|---|---|
| Onaylandı | `ad_approved` |
| Reddedildi | `ad_rejected` |
| Süresi doldu | `ad_expired` |
| 1 hafta kaldı | `ad_expiring_7d` |
| 1 gün kaldı | `ad_expiring_1d` |
| Boost onaylandı | `boost_approved` |

`notified_7d`/`notified_1d` bayrakları aynı mailin iki kez gitmesini engelliyor. Cron her gün 09:00'da `ad_send_reminders()` çalıştırıyor.

Metin senin istediğin gibi: *"Reklam süreniz bitmek üzere. Anlaşmamızı yenilemek veya yeni teklif göndermek için bizimle iletişime geçebilirsiniz."*

## 13. Medya kütüphanesi ✅

**Navbar → İletişim → Medya**. `medya` bucket'ı. Yükle · ızgara görünüm · önizleme (görsel + video) · dosya yolu ve URL kopyalama · klasör · etiket · açıklama · sil.

Dosya adları benzersiz: `<slug>-<YYYYAAGG>-<6 karakter>.<uzantı>` → `yaz-afisi-20260801-k4p1x2.jpg`

## Reklam medyası otomatik temizliği ✅

SQL Storage'a erişemediği için **kuyruk** kurdum:

```
Reklam görseli değişti / kampanya silindi
      ↓ trigger
storage_cleanup_queue (silinecek yol)
      ↓ panel worker (drainStorageCleanup)
Supabase Storage'dan gerçek silme
```

Tetikleyiciler: `trg_ad_media_cleanup_upd` (görsel/logo değişince eskisini), `trg_ad_media_cleanup_del` (kampanya silinince), `trg_media_cleanup` (kütüphaneden silinince).

Worker push dispatch'e bindirildi — ayrı cron gerekmiyor, hata olursa push'u etkilemiyor.
